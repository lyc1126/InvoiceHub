## 明细证据与校验

- 成本发票明细解析必须优先使用结构化或坐标来源：PDF 使用坐标/表格结构还原，XML 使用结构化明细节点，OFD 优先使用 `CustomTag.xml` 的明细字段引用，必要时才使用 `Content.xml` 文本对象坐标；不能只靠纯文本行号、抽取顺序或文件名硬拆。商品名跨行、OFD `item` 多段拆分、金额/税额先于数量/单价出现等情况必须在结构层或坐标层归位。
- PDF 业务版式成本明细必须先识别可靠表头，再按行基线映射列；建筑服务发生地/项目名称、旅客/货运专属列、不动产权证号等只能用于版式定位，不得挤入金额、税率或税额。无可靠表头时不得猜明细；同票候选优先选择除税金额和税额均校验通过的来源。
- 成本发票校验差异必须显式进入结果和页面，不得只写日志或在解析阶段吞掉。

## 产物与开票状态

- 成本分析 v1 产物固定写入当前选择器 `watch_dir`：
  - `watch_dir/成本发票明细.csv`
  - `watch_dir/成本发票汇总.xlsx`
  - `watch_dir/成本开票状态.json`
- `workspace` 只保留普通汇总与运行状态工作区；成本页面和 API 不得让用户误以为成本汇总表在 `workspace`。
- “刷新”和“重新汇总”语义必须分开：刷新只重新读取当前状态，不生成文件；重新汇总才扫描当前发票目录并重建普通汇总与成本分析。
- 成本分析表“开票参考”sheet 与 `/costs` 页面“开票参考”标签必须以当前成本明细为来源，按 `发票代码(**内文字) / 内部项目名称 / 规格型号 / 单位` 汇总；不能输出销售方和涉及发票号码；开票加价率不再固定，默认 `8%` 只作为行级 fallback，每条开票参考行可在 `watch_dir/成本开票状态.json` 中单独保存 `reference_markup_rate/reference_markup_rate_percent/reference_markup_locked`，勾选后的批量加价率操作只作用于已选行。API 必须持续暴露兼容字段 `reference_markup_rate`，但页面不得再提供顶部全局加价率设置。
- 开票参考按本公司税务设置计价：`watch_dir/成本开票状态.json` 顶层 `tax_profile = {taxpayer_type: general|small_scale, output_tax_rate, output_tax_rate_percent}`，缺失或不可读时按一般纳税人、13%，旧状态文件结果不变。成本单价 = sum(金额(除税) + 不可抵扣税金) / sum(数量)：小规模纳税人全部税金计入；一般纳税人只计入“发票校验”中已确认为增值税普通发票且非旅客运输的税金，类型未确认的按不含税计并在“成本口径”标注待核对，不得因识别缺口抬高参考价。参考税金与含税单价用 `tax_profile.output_tax_rate`。工作簿、`costs.py` 的读取与保存、`page-costs.js` 草稿联动四处必须同一公式；任何改写状态 JSON 的路径（含重新汇总合并工作簿状态）都必须保留 `tax_profile`。改税务设置不重算已开快照；页面有未保存的开票参考草稿时不允许保存税务设置。纳税人类型以公司清单为准（2026-11-10 用户决定）：`watch_dir` 所在公司在当月有登记时，类型取清单值、API 标 `taxpayer_source=company_registry`，在成本页提交不同类型必须被拒（400），销项税率仍按本页保存；有效类型不得写回状态文件。所有构造 `CostProjectionService` 与 `MonitorSynchronizer` 的位置都必须传入 `company_taxpayer` 查找（静态守护测试覆盖），否则工作簿与页面会按不同类型计价；清单改动使活动公司当月类型变化时，必须在投影写锁下重写工作簿，锁被同步占用时交给该次同步。购入成本按每张进项票的开票月份读取完整 `taxpayer_periods`，历史未覆盖或日期无效时成本单价未知并提示，不套用当前身份；销项税率仍使用保存设置。完整身份时间线纳入依赖键，无源文件变化的下一次同步也检查依赖并刷新工作簿，不重新提取原票。
- 开票参考的销项比对（COST-03）：只有手动“重新汇总”读取 `outbound_invoice_dir`（monitor 重建沿用上次汇总），解析结果与文件签名缓存只写 profile 工作区，不写 `watch_dir` 或开具目录。已登记公司采用同公司 `issued_invoice_dir` 映射，缺失或链接不得回退；只有未登记来源沿用全局设置，必须只采用销售方属于本目录进项购买方的发票，并显示被排除张数；开具目录与 `watch_dir` 重叠时不读取。同票多格式按发票号只计一次，红字票按负数冲减。手填 `已开数量` 始终是保存值：比对只显示销项数量、实际加价率（销项除税单价 / 成本单价 − 1）与“一致 / 销项多 / 手填多 / 销项超过进项”，“按销项更新”只写页面草稿，保存仍走既有快照语义。全部已对上品目（至少 3 个）实际加价率相同时只提示留存定价依据，不改金额。读取失败只记提示，不使重新汇总失败。比对以“库存数量与票面一致”为原则：开票中价格变动属正常，实际加价率只中性展示、不因偏离参考价告警；数量差异必须醒目（待更新为警示色，销项超过进项为危险色），面板按全部行统计数量一致 / 待更新 / 销项超过进项 / 无销项。`/costs` 开票参考表的数量列（数量、已开、销项、数量比对、未开、开票状态）必须连续排在价格列之前；草稿联动按列 key 定位单元格，列顺序与 `#referenceTable` 列宽必须同步。
- 品目表（COST-02）：存于 `成本开票状态.json` 顶层 `item_catalog`，与 `tax_profile` 同属公司级设置，所有状态写入路径都必须保留。开票参考、工作簿、销项比对与保存都先经 `canonical_reference_rows` 归一：名称换成标准名称（改名即合并，链式改名按最终名称），规格只统一全角半角与空白（不改大小写、不去 E 后缀），非货物（费用 / 固定资产）不进开票参考但保留在成本明细与项目规格汇总；品目税率覆盖公司税率。本系统不建科目体系，科目对照另行从账套读回。改品目表时已保存的已开状态必须一次性迁移到新分组：合并按成员已开数量与快照金额相加，拆分按数量比例分配，二者在已开数量非零或加价率不一致时标“已开数量待核对”，直到该行再次保存；退出开票参考的名称保留原状态，改回后恢复。页面有开票参考草稿时不允许保存品目表。
- 开票参考移除：`成本开票状态.json` 顶层 `reference_exclusions`（`keys` 品目行、`invoices` 来源发票，带显示信息与移除时间）只把内容排除出开票参考、其统计、工作簿“开票参考”sheet 与销项比对，不删除或移动任何文件，不改成本明细、项目规格汇总与已保存的已开状态；恢复后原样回来。来源发票按发票号码（无号码时按源文件名）整张移除，其它品目行中的同票明细一并排除，页面必须说明。有未保存草稿时禁止移除。所有状态写入路径必须保留 `reference_exclusions`。
- `/costs` 操作区：命令栏只放视图切换、刷新、唯一主按钮“重新汇总”与“更多”（打开成本分析表、复制当前表格）；品目表入口在“本公司设置”面板；开票参考的批量操作与保存只出现在底部浮出操作条（勾选时显示已开数量 / 加价率 / 移除 / 取消选择分组，有草稿时显示未保存行数、放弃修改与保存），Esc 先关菜单再取消勾选；操作条出现时内容区预留底部空间。“全选”覆盖开票参考全部页（同一修订号逐页读取，修订号变化即中止），“清空全选”在面板与操作条都可用。切换 sheet 或翻页属于视图切换：不显示读取进度条、不整页重绘，只渲染要显示的 sheet；未渲染的 sheet 先保持原高度，渲染后先按新行数测量表格高度再释放，避免页面变短把滚动拉回顶部；后台自动刷新若修订号未变只更新状态文字，不重建表格；文字类更新值不变时不写入 DOM。修改 `web/static` 后必须升级资源版本，否则已打开过的浏览器会继续用缓存旧脚本。
- 开票参考状态保存时必须按同一汇总键持久化到当前 `watch_dir/成本开票状态.json`，并锁定当次 `已开数量` 与已开参考金额/税金/价税合计快照。后续新增同键发票只能增加未开部分，不能让已开金额随新汇总漂移。
- 底层 `成本发票明细.csv` 必须保持一条明细一行、票面字段不留空；工作簿和页面可以合并展示同票票面字段，但不能改变 CSV 逐行口径。
- 调整成本字段时必须同步更新工作簿 sheet、`GET /api/v1/cost-analysis`、`POST /api/v1/cost-analysis/reference-status`、`/costs` 前端和契约测试。

## API 与页面契约

### 公司 V2 核对、留痕和分析（2026-11-21）

- 显式库存科目对照、期初与完整读回月份声明仅在预览确认后写公司根目录 `库存科目对照.json`，绑定当前账套语义；只选择已启用末级库存科目，不另建科目。V2、进销存比较与凭证草稿共用解析及原加权核心，同科目品类+单位滚动，规格不分摊。确认基线是预期滚动起点，早前发票不重复计入，也不自动纠正已确认期初。
- 月末账面差额=账面−发票滚动，只有明确期初/对照、每月完整声明及实际读回、单位与来源可靠才计算；无基线/缺月/非月末/重复库存行/数量方向不明/单位冲突/卖超/排除为待核对，未知差额 null，不填零。未匹配非零科目单列，不以最后读回月或文件名推断连续覆盖。坏/过期映射不得回退旧品类掩盖问题。
- 报价/规则试算有独立归档预览及确认，冻结原请求、成本、规则版本、市场来源/有效期与原结果；普通报价/预览不留痕。归档绑定公司/修订/来源与内容 hash，原子写根目录 `成本报价记录.json` 后读回；同ID同请求重放取原回执，异内容拒绝，源目录移走仍能查历史。显式确认归档内容 hash 后导出内存 XLSX，不重算、不改旧工作簿，数字和用户文字按文本保存。
- 实际货物分析按品类单位、客户、项目、月份汇总除税收入与原月销售成本；客户/项目累计数量分位分摊须守恒，不建立规格库存。缺成本、缺数量、卖超或来源不完整不得补零；当前月只到今天且标暂计，拒未来月。项目沿既有人工/备注优先级，来源可追溯；非货物收入明确列入排除原因。
- 服务成本遵用户选择按月份/项目明确录入金额与来源，预览确认写根目录 `服务成本归集.json`；不从工资/社保推算、不自动分摊到客户/品目。分析单列，不从货物毛利扣除或声称服务毛利/公司净利润。服务收入匹配仍列后续。
- 监控提供采购波动、成本异常、实际低毛利、最近销项一致票面税率及设置差异；票面不证明税率适用，不自动修改税率/价格，不联网采价或因售价偏离参考价告警。统一加价率/疑似同物异名提示仍待做。
- 三份人工文件均有界且绑定公司，不进入 monitor 投影/SQLite 发票主存储；GET/quote/preview 不写盘。保存在成本锁内重新核对来源，库存配置另取草稿写锁，原子替换读回；无外部编辑器/CLI 跨进程事务保证。坏文件保留拒写，未知保存结果先查询。旧 v1、已开快照及既有工作簿未切换；前端/迁移/真实与平台验收仍列 COST-04/05/06。

### 公司 V2 首批后端（2026-11-19）

2026-11-20 第二批补充：tiered 以单行数量或显式 tier_amount 除税基准金额分档，整行采用命中档价格；起点零、严格递增、半开区间、最多 50 档，不递归或反推金额。market 使用当前请求的人工市场参照，必须带价格口径、来源与有效期；不联网、不写规则文件。缺证据/过期/未知成本保留待核对，不回退默认价。最低加价底线在取整后仍须成立且优先于尾数；原最低毛利仅提示。上下文与完整证据均绑定 preview_hash，修改后重新试算。六类规则后端已实现，归档/分析的后续当前进度以上方 2026-11-21 为准。

- `/api/v1/companies/{company_id}/cost-analysis/v2` 与其 quote/rules 接口只消费登记公司两侧上次完整投影，按计划日期截断原始明细；不得切监控目录、触发汇总、修复旧状态或工作簿。坏 manifest 保留并拒读，不回退固定导出副本。
- 库存复用现有品类 + 单位的 `cost_of_sales`，规格不分摊成本。结存成本不可用必须 null，不偷换历史均价；历史身份未知、卖超、排除、过期/不完整来源均披露。活动监控目录仍核对新鲜度，不能把 monitored 视为 fresh。
- 人工规则独立写本公司成本目录 `成本定价规则.json`，包含 version/revision/company_id/rules；monitor 与 v1 不重写它。规则/报价金额使用 Decimal 字符串；非法/非有限/超限值拒绝。固定含税价/含税取整以含税总额为权威反算除税总额与税额，不通过已舍入除税单价二次换算。
- 保存必须重新计算候选规则的 before/after，核对成本 revision、规则 revision、preview_hash 与 confirm；同进程锁内重核完整投影、公司目录/账套来源/规则指纹，原子替换并读回。坏文件、公司身份不符、重放、目录替换和链接拒绝；未知写结果只能查询，无外部编辑器/CLI 跨进程事务保证。
- 旧人工行级加价只读迁移，自动生成默认率不能盖过客户规则。实际销项和手填已开快照分列且不相加，规则保存不改变旧快照、工作簿或 v1 价格。科目映射、归档与分析的当前进度以上方最新日期为准，V2 页面及工作簿切换仍按 COST-06 后续实施。

- 分页读取缓存仅作可重建投影：完整四标签同代际原子发布，读取繁忙时保留上次完整结果而不取消原写锁；首次无完整结果只展示临时明细，停止/失败不能把临时结果升级为可编辑状态。
- 分页保存须校验页面的 target_id/revision，不能将旧草稿静默套用到新汇总；跨页选择、数量/加价草稿和全量 TSV 复制语义保留，复制过程中代际或目录变化须中止。旧完整 API 保持兼容。

- `/api/v1/cost-analysis` 必须持续返回：
  - `watch_dir/source_dir/target_id`
  - `output_detail_csv_path`
  - `output_summary_xlsx_path`
  - `reference_status_path`
  - `invoice_reference`
  - `reference_status_stats`
  - `reference_markup_rate`
  - `reference_tax_profile`（纳税人类型、销项税率、是否已保存、提示）
  - `reference_exclusions`（已移除的品目行与来源发票、是否仍在明细中、总数）
  - `item_catalog`（发票名称、标准名称、类型、税率、规格数、单位、数量合计）

  - `sync`

## 工作区公司口径（B6，2026-11-17）
