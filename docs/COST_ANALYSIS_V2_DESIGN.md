# 成本分析 v2 设计（未实现）

本页是成本分析与开票参考下一版的设计提案，不代表已实现能力。现行规则以[成本明细与开票参考规则](architecture/rules/COST_ANALYSIS.md)、[数据与算法 §8—9](architecture/DATA_AND_ALGORITHMS.md)和源码为准。落地拆分见[未来工作总览 COST-06](PRODUCT_BACKLOG.md#cost-06)及其关联的 COST-01—05、[BUG-01](PRODUCT_BACKLOG.md#bug-01)。

## 0. 已确认的决策（2026-11-05）

| 问题 | 结论 |
|---|---|
| 售价是否因客户而变 | 会变。定价按“客户 × 品目”取用，页面以“先选客户 / 数量，再给参考价”为主（§7）。 |
| 定价方式 | 要多样，不能只有加价率。六类规则都保留，分两批实现（§6.1）。 |
| 销项税率 | 多数 13%；部分公司是小规模（3% / 1%），劳务类公司也有 3%、1% 等。税率按公司与品目设置，不得写死（§5，BUG-01）。 |
| 成本口径 | 默认用“结存加权单价”（与做账结转同一算法），并列显示“最近一次进价”；先进先出与移动加权不进首版（§4.2）。 |
| 规则层级 | 首版 4 层：单行手动 > 客户 × 品目 > 客户 > 品目 / 公司默认；项目、品类两层按需再加（§6.2）。 |
| 比对原则（2026-11-08） | 以“库存数量与票面一致”为先；开票中价格有变动属正常，实际加价率只作参考、不告警（COST-03 已按此排版）。 |
| 科目设置（2026-11-08） | 本系统不另建科目体系，账套是科目与账本的真值。只维护品目表（名称、别名、类型、税率，人工可改）；需要科目时从读回的账套科目表选择对照，做账时再接入；固定科目（应交税费、收入、往来）按导入模板每家公司配一次（BK-01）。 |

## 1. 现状与问题

- 数据范围只有当前 `watch_dir` 的成本发票，开票参考按 `发票代码(**内文字) / 内部项目名称 / 规格型号 / 单位` 分组，参考除税单价 = 该组**全部历史进项**加权均价 × (1 + 加价率)。
- 加价率只有一种形式：每行一个比例，默认 8% 兜底；批量操作也只能改比例。用户实际定价往往是“按客户 / 项目谈的价”“保证最低毛利”“取整到元”“量大优惠”，现有模型表达不了。
- 不读销项发票：已开数量靠手填，看不到实际加价率（COST-03）；已卖出的批次还留在均价里（COST-01）；同一材料不同叫法被拆组（COST-02）；与做账库存不互通（COST-04）；售价完全跟随成本，有统一加价率的风控隐患（COST-05）。
- 税写死：销项税率固定为 `REFERENCE_OUTPUT_TAX_RATE = 0.13`（`projections/cost_analysis.py`），成本固定取不含税金额。小规模纳税人进项不能抵扣、销项按征收率开票，两处都会算错（BUG-01）。
- 与做账库存粒度不同：成本分析分到规格；做账库存（`bank/vouchers.py` 的 `cost_of_sales`）按账套库存明细科目滚动，发票品名靠写死关键字的 `goods_family()` 归到科目，不分规格。

## 2. 目标

1. 成本口径与做账一致：同一家公司只有一套品目台账，成本分析、做账结转与比较页读同一个计算结果。
2. 定价灵活但可解释：每个参考价都能说清“命中了哪条规则、怎么算出来的”。
3. 税按公司与品目取：进项税是否进成本、销项税率 / 征收率都来自设置，页面可见、可改。
4. 保留现有兼容：`watch_dir` 三件套、`成本开票状态.json` 的已开快照与 API 兼容字段 `reference_markup_rate` 不得丢失或漂移。

## 3. 数据底座：公司级品目台账

### 3.1 品目表（一张表，用户维护）

| 字段 | 说明 |
|---|---|
| 标准品名 / 规格 / 单位 | 分组键；规格做大小写、全半角、空格规范化，不自动猜测不同规格相同 |
| 别名 | 不同供应商、不同发票上的叫法，归一到标准品名（COST-02） |
| 账套科目对照（可选，第二层） | 从读回的账套科目表中选择库存明细科目，多个品目 / 规格可对同一科目；系统按名称给建议、用户确认；账套没有的标“账套缺此科目”并列入导出的“待新增科目”，本系统不新建科目。做账时接入，取代写死的 `goods_family()` |
| 类型 | 货物（有数量、滚动结存）/ 服务（劳务、运输、加工等，无库存） |
| 默认销项税率 | 空时取公司设置（§5） |

- 接入科目对照时，按现有 `goods_family()` 的关键字和历史发票预填建议，用户确认后保存；未对照的品目显示“未对照”，不静默并入其他科目。
- 状态持久化沿用公司资料夹 / `watch_dir` 状态文件，旧分组键可迁移。

### 3.2 按月滚动

- 来源：成本发票明细（购入）、开具发票明细（销售）、账套读回的期初结存（没有时为 0，并提示）。
- 逐月：月初结存 + 本月购入 → 本月结存加权单价 → 本月销售成本 → 月末结存。与做账库存核对共用 `cost_of_sales` 同一函数，比较页的守恒校验（期初 + 购入 − 销售成本 = 结存）在后端计算并返回。
- 结存一致在**科目层**校验：同一库存科目下各品目结存合计 = 做账库存核对的科目结存。规格层只是科目的拆分明细。
- 服务类品目不滚动结存，只进毛利分析（§7）。
- 金额全部按 Decimal 字符串处理，四舍五入到分；数量保留原始精度。

### 3.3 品目表首版范围（COST-02，2026-11-08 开工）

- 存放：`watch_dir/成本开票状态.json` 顶层 `item_catalog`，与 `tax_profile` 同样随公司资料夹走；任何改写状态的路径都要保留它。
- 每个品名一条：`名称`（发票上的内部项目名称）→ `标准名称`（默认等于自身，改成另一个名称即合并）、`类型`（货物 / 费用 / 固定资产，默认货物）、`销项税率`（空 = 跟随公司税务设置）。
- 归一：分组键 `发票代码(**内文字) / 内部项目名称 / 规格型号 / 单位` 中的名称换成标准名称；规格只做全角半角与空白统一（不改大小写），**不去掉 E 后缀**（`18E` 与 `18` 是不同牌号）。没有品目表或未改名时分组键与现在完全相同，旧状态无需迁移。
- 合并后的已开状态：新分组没有保存过时，按成员旧分组的已保存状态合计（已开数量与已开快照金额相加，加价率不一致时取数量最大那组并标注）；保存后写到新键并移除旧键。拆开（改回原名）时按同一规则反向读取。
- 类型不是货物的（如油品、电梯）不进开票参考与其统计，仍保留在成本明细与项目规格汇总。
- 品目税率覆盖公司税率，只影响该品目的参考税金与含税单价。
- 页面：`/costs` 提供“品目表”弹窗，列出发票上出现过的全部名称（规格数、数量合计、单位），可改标准名称、类型、税率；保存后重算开票参考与工作簿。
- 不做：科目对照（第二层）、按规格设置别名、自动猜测同品。

## 4. 成本基数

### 4.1 进项税是否计入成本

| 情形 | 成本金额 |
|---|---|
| 公司是一般纳税人，进项为专票且已勾选抵扣（进项抵扣目录） | 不含税金额 |
| 公司是一般纳税人，进项为专票但尚未勾选 | 暂按不含税金额，标注“抵扣待确认” |
| 公司是一般纳税人，进项为普票等不可抵扣凭证 | 价税合计 |
| 公司是小规模纳税人 | 价税合计（进项不能抵扣） |

- 公司纳税人类型来自公司设置；可抵扣凭证范围与例外（如旅客运输）以[税务工作台政策中心](TAX_ALGORITHMS_AND_POLICY.md)为准，不在成本模块里另写一套。
- 页面每行标注成本取的是“不含税”还是“含税”。

### 4.2 成本口径

| 口径 | 算法 | 首版 |
|---|---|---|
| 结存加权单价（默认） | 按 §3.2 月末一次加权滚动后的月末结存金额 ÷ 结存数量 | 是 |
| 最近一次进价 | 最近一张进项的单价，只作对照列 | 是 |
| 移动加权 | 每次购入后重算单价 | 否 |
| 剩余批次先进先出 | 按未售出的批次计算剩余成本 | 否 |

- 为什么默认用结存加权就够：每月卖出的数量按当月加权单价从库存里扣掉，老批次会按比例逐月退出，参考价不再一直混着很早以前的进价（COST-01 的主要问题）；而且与做账结转同一个数，不会出现“参考表一个成本、账上一个成本”。进价涨跌很快时，看并列的“最近一次进价”。
- 先进先出要把每笔销售对到具体批次，销项发票上没有批次信息，只能人为假设；又与做账结转口径不一致，所以首版不做。
- 口径只影响参考价，不改变做账结转（做账固定用公司设置的口径）。

## 5. 销项税率与计税方式

- 取用顺序：规则或单行指定 > 品目默认税率 > 公司设置。公司设置写明纳税人类型和默认税率 / 征收率（一般纳税人常见 13%；小规模 3%，或按现行优惠减按 1%）。
- 征收率与优惠的适用期来自[税务工作台政策中心](TAX_ALGORITHMS_AND_POLICY.md)，代码不写死；政策过期或未核验时页面提示，不自动切换税率。
- 读取销项发票时，把该品目最近使用的税率作为建议显示；与设置不一致时提示（例如小规模公司出现 13% 票面），不自动改设置。
- 换算：含税单价 = 不含税单价 × (1 + 税率)，四舍五入到分；规则录入含税价时按同一税率反算不含税价。
- 差额征税等特殊计税方式（如劳务派遣选择差额纳税）首版不计算，该品目标注“特殊计税，需人工确认”，计算留给税务工作台。

## 6. 定价规则（取代单一加价率）

### 6.1 规则类型

| 类型 | 参考除税单价 | 说明 | 批次 |
|---|---|---|---|
| 加价率 r | 成本 × (1 + r) | 兼容现有字段 | 首批 |
| 目标毛利率 m | 成本 ÷ (1 − m) | 与加价率换算：r = m ÷ (1 − m)，页面两者同时显示 | 首批 |
| 固定加价额 a | 成本 + a | 运费、加工费类加价 | 首批 |
| 目标价 / 合同价 | 用户录入的固定价（可填含税或不含税） | 合同约定价，偏离成本时提示 | 首批 |
| 阶梯 | 按本次开票数量或金额分段取上面任一类型 | 量大优惠 | 第二批 |
| 市场价参照 | 市场价，但不低于“成本 × (1 + 最低加价率)” | 跟市场走，同时守住底线 | 第二批 |

附加项（首批）：取整（到角 / 元 / 指定尾数）、含税价取整后反算不含税价、最低毛利保护（低于时不改价，只标红提示）。

### 6.2 作用范围与优先级

- 首版 4 层：单行手动 > 客户 × 品目 > 客户 > 品目默认 / 公司默认。项目、品类两层在用户确有需要时再加。
- 同一层同一对象在同一时间只允许一条规则生效：保存时校验生效期不重叠，冲突直接拒绝，不靠“取最新”暗中覆盖。
- 规则都带生效起止日期，按计划开票日期（默认今天，可改）选用；页面列出被更高层覆盖的规则。

### 6.3 可解释与试算

- 每个参考价旁显示“命中规则 + 代入式”，例如“客户 A × 钢筋：目标毛利 12% → 3,934.06 ÷ (1 − 12%) = 4,470.52，取整到元 → 4,471.00；税率 13% → 含税 5,052.23”。小规模示例：“成本（含税）1,030.00 × (1 + 10%) = 1,133.00；征收率 1% → 含税 1,144.33”。（示例为合成数字。）
- 改规则前先“试算”：列出受影响的行与新旧参考价，确认后才生效。

### 6.4 已开部分与快照

- 读取销项发票后（COST-03），已开部分直接以**实际发票金额**为准，不再拿参考价推算。
- 只有用户手工补填的已开数量，才沿用现有已开快照语义锁定当次参考金额；之后改规则或成本变化都不改已开金额。
- 显示实际售价对应的实际加价率 / 毛利率与规则的偏差（COST-03）；所选期间全部销项恰好同一加价率时给风险提示，提醒留存定价依据（COST-05）。

## 7. 页面结构

1. **定价助手（开票参考）**：先选客户、计划开票日期和数量，再给出各品目参考价、命中规则与代入式；支持批量试算、导出报价单。未选客户时按“品目 / 公司默认”规则显示。
2. **品目总览**：每个品目的结存数量、结存加权单价、最近进价、进价走势、已售数量、成本含税与否、税率、库存科目映射状态。
3. **毛利分析**：按品目、客户、项目、月份看销售收入、销售成本、毛利与毛利率，点开可看来源发票（与比较页明细同一交互）；服务类品目在这里按期间 / 项目对照收入与成本。
4. **价格监控**：进价异常波动、售价低于成本或最低毛利、统一加价率风险、票面税率与公司类型不符、品名未归一的疑似同品、未映射库存科目的品目。
5. **规则与品目管理**：品目表（别名、科目、类型、税率）、规则列表、优先级、生效期、试算记录。

## 8. 兼容与迁移

- 旧状态中每行的 `reference_markup_rate/reference_markup_rate_percent/reference_markup_locked` 迁移为“单行手动 · 加价率”规则。
- 一般纳税人公司：迁移前后参考价逐行一致才启用新页面。小规模公司：旧结果按 13% 和不含税成本算，本身是错的（BUG-01），迁移时显示新旧对照与差额，由用户确认后启用。
- `GET /api/v1/cost-analysis` 继续返回 `reference_markup_rate` 等现有字段；新增字段只增不改。
- 工作簿“开票参考”sheet 增加“命中规则”“成本口径”“成本含税”“税率”列，原有列顺序不变。

## 9. 落地顺序与验收

1. **品目表与税设置**（COST-02、BUG-01；公司级税务设置与进项税计入成本已于 2026-11-05 先行实现，见 BUG-01；品目表首版（名称归一、类型、品目税率）2026-11-08 实现，科目对照待做账接入）：品目归一、挂库存科目取代 `goods_family()`；公司纳税人类型与品目税率生效。验收：合成数据中做账库存与成本分析在科目层结存一致；小规模合成公司参考含税价按含税成本与征收率计算；一般纳税人结果与现在逐行一致。
2. **读取销项**（COST-03、COST-05 提示部分；2026-11-06 已实现，手填已开数量保留为保存值，销项只比对并可“按销项更新”草稿）：已开数量自动累计、实际加价率、统一加价率提示、税率不符提示。这一步不改任何定价，优先做。
3. **成本基数**（COST-01、COST-04）：结存加权单价 + 最近进价；与账面库存核对。验收：先进低价、后进高价的合成批次部分开票后，结存加权单价只反映结存部分。
4. **定价规则引擎首批**：四种规则、取整、最低毛利保护、4 层优先级、生效期不重叠校验、试算；旧状态迁移。每种规则类型、每层优先级、生效期边界都有单元测试。
5. **第二批与分析页**：阶梯、市场价参照，毛利分析与价格监控。

每一步都要同步工作簿、API、`/costs` 页面与契约测试，并遵守[成本规则](architecture/rules/COST_ANALYSIS.md)中“刷新只读状态、重新汇总才生成文件”的语义。

## 10. 未决事项

- 差额征税等特殊计税方式的参考价算法（交给税务工作台设计）。
- 服务类品目的成本怎么归集（人工、分包、社保等来自哪些目录），首版只做收入成本对照。
- 是否需要项目、品类两层规则。
