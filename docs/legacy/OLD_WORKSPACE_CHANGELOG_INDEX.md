# 旧工作区功能与故障回溯索引（脱敏）

## 目的与边界

本索引用于在排查历史功能或回归问题时快速定位可能相关的设计原因、当前
实现和守护测试。它不是旧工作区原始 `CHANGELOG.md` 的副本，也不构成公开
发布、迁移验收或当前实现的证据。

- 只保留可公开的功能类别、常见症状、长期不变量和当前查询入口；不复制
  原始标题、日期、提交、路径、主体、业务数据、构建信息、运行状态或验证
  叙述。
- 原始变更记录只保留在所有者私有归档中，必须在公开工作树外读取。不得将其
  原文、附件、软链接、绝对路径或局部摘录复制、链接、暂存、提交或写入
  ignored 运行目录。
- 当前源码、测试和真值文档优先于本索引。本索引只能说明“应从哪里核对”，
  不能据此恢复已退休的目录、版本、发行身份或未启用能力。

## 查询顺序

1. 先阅读根目录 [变更日志](../../CHANGELOG.md)、[旧项目能力基线](../BASELINE_FROM_OLD_PROJECT.md)
   和相关当前真值文档，确认问题是否已在公开实现中被重新定义或取代。
2. 按下表的关键词进入当前架构、源码和测试，核对实际接口、数据、状态和
   验收边界。
3. 只有当前公开资料不足以解释某项兼容保护时，才由所有者在私有归档中人工
   查证；回写公开仓库时只能新增经过脱敏的结论、原因、不变量和测试入口。
4. 不以“旧记录存在”为理由恢复旧提交、旧包、旧配置、旧路径或旧发布证据。

## 维护要求

- 新增索引项只能描述公开可验证的类别和不变量，不得逐段转写私有记录。
- 当一个历史问题产生新的公开保护逻辑时，记录当前代码符号、测试和失败后果；
  不记录私有环境、人员、路径、数据、提交或收据。
- 如果无法在不泄露资料的前提下形成足够具体的公开结论，停止在本索引处，
  由所有者在私有环境继续查证，不把原文带入本仓库。
