# 税务算法、政策依据与验收样例

> 2026-09-11 · 配套[工作台设计](TAX_WORKBENCH_DESIGN.md)与[政策来源、核验与政策中心](TAX_POLICY_SOURCES_AND_REVIEW.md)。本文是待实现的受限算法规格，不是当前 main 已有能力，也不是企业纳税申报结果。所有算例均为重新构造的合成数据。

## 1. 数值和证据合同

- 金额、数量、税率以十进制字符串进入后端，Python `Decimal` 运算；不用 JS `Number`、API float、二进制浮点或动态 `eval`。
- 金额单位固定人民币元；税率 `0.13` 表示 13%，印花税 `0.0003` 表示万分之三，不能将 `%`、`‰`、万分数混同。
- `null` 表示未知；合法 `0.00` 需来自输入或“已确认无事项”。检查非有限值、指数格式、超过长度/精度/额度、除零、不允许的负数。建议金额上限沿用旧 MVP 的 `999999999999.99`，精度和资源上限在模型中固定。
- `Q2(x)` 表示本测算模式按 `ROUND_HALF_UP` 到分；金额源记录保留原值，不在读取阶段反复四舍五入。数量和单价保留各自精度。票面已开具金额以来源为准，复算差异只报告，不覆盖源票。
- 舍入是算法的一部分：保存 `rounding_policy_id / precision / rounding_points`。基础价税换算规则可以固定；税种申报表的行级、优惠、分项、合计舍入位置必须分别核验，未核验不能宣称与申报系统到分一致。
- 每次计算记录规范化输入、事实快照、公式版本、规则包内容 hash、解释模板版本、逐步操作数/精确值/舍入值及来源。可重放指纹不含生成时间；同一输入与规则得到相同数值和解释。
- 结果必须随附规则包版本与 `coverage_through`；属期超出已核验覆盖范围时，自动结论降级为待核对，不能沿用规则包最新版本的名义继续给出确定金额。

## 3. 价税换算

适用前提：单一税率、普通价外税交易、无差额或减征计税特殊分母。此处计算票面价税关系，不计算公司当期应缴。

设不含税金额 `N`、增值税额 `T`、价税合计 `G`、适用税率 `r`：

```text
T = N × r
G = N + T = N × (1 + r)
因此 N = G ÷ (1 + r)，T = G − N

输入不含税：N = 输入，T = Q2(N × r)，G = N + T
输入含税：  G = 输入，N = Q2(G ÷ (1 + r))，T = G − N
```

例如 `G=113000.00, r=0.13`：`N=100000.00, T=13000.00`。不能用 `113000 × 13%` 求税额，因为含税金额已经包含税。

同票多税率按可靠明细分别计算；不得给票头套平均税率。免税、零税率、不征税与未识别是不同法律状态，即使数值都可能没有税款也不能都编码为 `rate=0`。仅有税额且 `r=0` 时不能反推价款。

## 4. 一般纳税人月度增值税

首个自动场景限定：境内普通一般计税交易，来源和抵扣确认完整，无特殊申报项目、混合简易计税、出口免抵退、留抵退税、查补或跨地区预缴。

```text
O_m = 本月税务义务归属的销项税额（含已确认未开票业务及有证据的红字调整）
I_m = 本月已确认可抵扣进项税额（含合法非普通发票扣税凭证）
X_m = 本月应转出进项税额
L_(m−1) = 经核对的上期期末留抵

净额 D_m = O_m − I_m + X_m − L_(m−1)
本月一般计税应纳测算 A_m = max(D_m, 0)
本月期末留抵测算 L_m = max(−D_m, 0)
```

这是限定场景的余额关系，不是所有增值税申报表的完整公式。`X_m` 不直接裁成不大于本月进项；其业务原因和来源必须验证。特殊调整、退税、应抵欠税/实际抵扣限制等有非零事项时，切换已实现的专用算法，否则阻断“完整应纳”。

预缴、已缴和应纳分栏：在税款归属、可抵范围、使用顺序及申报口径已核验后，才另算本期应补。已缴不是减免，不减少应纳本身；不能把完税凭证金额再当“进项”扣一遍。

按月申报公司的季视图必须先逐月计算再加应纳额，不能季度先轧差。反例：1月销项 10,000、进项 0；2月销项 0、进项 10,000；3月无业务。应纳累计 10,000，季末留抵 10,000；把季度总销项减总进项会错误得出应纳 0。

小白背面：销项税是销售环节计算的税；能抵扣的进项和原有留抵用于减少本期应纳。购进票不一定已用于本期抵扣；剩余留抵不是当前银行到账的退款。

## 5. 小规模纳税人

纳税人身份、计税周期和交易适用范围必须先确定。2026-01-01 至 2027-12-31，月起征点 100,000 元、季起征点 300,000 元，按次（日）另有 1,000 元起征点；首轮自动只做公司按月/季的普通境内交易。

```text
S = 按当期适用规则确认的全部应税交易销售额
H = 100000（月）或 300000（季）
threshold_exempt = S < H
```

S 包括应计入起征点口径的未开票、专票等交易，不能仅统计“普票文件夹”；差额业务的起征点口径按 S7 第一条另行实现。未达到起征点但放弃免税开专票的交易单独处理。

在 S7 第三条（三）6 和 S8 范围内，一般普通交易可按 3% 征收率减按 1% 征收率，排除销售/出租不动产或转让土地使用权；销售已使用固定资产/旧货等另有规则，不能只凭“小规模”覆盖。

```text
对每组已确认适用的交易：
  符合免税且未放弃：应纳 = 0
  应税且适用减按1%：应纳 = 不含税销售额 × 1%
  已确认放弃减税的相应交易：按对应法定征收规则计算
合计 = 各组按其舍入节点完成的应纳税额之和
```

售价分离的分母率与实际计税率分别建模：`price_divisor_rate`、`levy_rate`、`relief_method`，不能把所有“3%减按X%”统一改成含税额除 `1+X%`。1% 开票模式与按规定征收率计算销售额的其他减征项目必须分别有政策/申报样例。

边界样例（2026 年，普通符合 1% 范围、全部不含税销售额、无放弃免税交易）：月 99,999.99 为免税；100,000.00 达到起征点，应纳 1,000.00；100,000.01 按全额计算，最终到分 1,000.00。季度对应 299,999.99 / 300,000.00 / 300,000.01，后两者不是只对超额部分计税。历史期间必须选择历史规则包，不能机械套上述比较符。

## 6. 附加税费

城市维护建设税、教育费附加、地方教育附加分别是独立叶子项。常见税率分别为所在地适用的 7%/5%/1%、3%、2%，税务资料必须确认所在地及地方适用口径。

```text
B_j = 经该税费规则确认的计税依据
税额精确值 = B_j × r_j
如该项有完全免征资格：应纳 = 0
否则如有六税两费减半资格：应纳精确值 = B_j × r_j × 50%
否则：应纳精确值 = B_j × r_j
各项在规则指定节点舍入，附加合计 = 三个已舍入叶子项之和
```

S12 的“依法实际缴纳”有法定计税定义，不等于只读取银行付款额：以依法应当缴纳的两税税额（不含进口/指定境外交易）为起点，加免抵税额，扣直接减免和按规定可扣的留抵退税。先征后返、先征后退、即征即退不能直接当作“直接减免”。三项附加的基础在 S12 范围内一致，税率、优惠与结果仍分别计算。

一般境内普通场景可由完整且已确认的 VAT/消费税计算事实形成联动测算依据，不必等银行付款才算附加；源票销项税额不能自动充当 B。联动结果标记“测算”，不能伪称税款已经支付。若输入已经是减免后的两税应纳额或已调整计税依据，不再二次减除对应减免/退税；输入必须声明其所处计算阶段。

S4、S12 对进口/境外交易、留抵退税、免抵等有专门口径；必须拆分排除项与调整来源，禁止把所有税款支付金额相加。首轮若存在这些特殊事项，要求已确认的分税费计税依据或返回未支持。

六税两费：S6 在规定期间对小规模、小型微利、个体工商户减半。一般纳税人也可能按小型微利资格享受，但不能只凭一般纳税人标签决定。资格和生效期间取有依据的事实，用户随手勾选只是手工测算假设。

教育费及地方教育附加的 S9 免征先独立判断，`月销售额 ≤ 100000 / 季销售额 ≤ 300000`；完全免征后这两项为零，不能又减半出负数。城建税没有因此自动免征。不能把 VAT 的 `< H` 比较符共享过来。

合成普通例：已确认 B=3,000，所在地城建 7%，教育 3%，地方教育 2%，六税两费资格成立，教育费完全免征不成立：应纳分别 105、45、30，合计 180。若 B=1,000、月销售额恰为 100,000，且满足上述教育费免征与六税两费条件，则本例只有城建 35，教育/地方教育为零；不能一律算 1,000×6%。

舍入反例：B=0.10，r=7%，减半。直接在最后取分为 `Q2(0.0035)=0.00`；先把减免前税额取分再减半则可能为 0.01。必须为该税种选择经过核验的舍入节点；缺申报表样例时仅保留明确注明精度策略的手工测算，不能自动宣称到分一致。

## 7. 印花税

计税对象是列举的应税合同、产权转移书据、营业账簿等，不是全部发票、收付款或 PDF 文件。首轮支持明确选定的常见税目；合同名称/商品关键词只能提示待选，不能自动作税目认定。

```text
合同/书据列明价款 M，单独列明 VAT 为 V：计税依据 B = M − V
未单独列明 VAT：不能仅凭“含税”或关联发票自动除税；按适用规则确认 B
未列金额：按实际结算金额；仍不确定再按法律规定处理，不能填零
从价应纳 = B × 该具体税目税率
```

同合同分别列明多个税目金额，逐项适用；未分别列明按 S3 第九条处理。多方合同按各自涉及金额，不默认均分或乘以双方人数。采购与销售合同可以分别应税，但同合同对应多张发票不得重复计算。红票不自动等于印花税退款，合同变更/退还单走对应事实和规则。

首批表：买卖/承揽/建设工程/运输/技术合同 `0.0003`；借款和融资租赁合同 `0.00005`；租赁/保管/仓储/财产保险合同 `0.001`。税目适用范围必须保留，例如借款合同有金融机构等范围，不能把任何股东借款都套上。

产权书据中土地/房屋/股权等通常 `0.0005`；商标专用权、著作权、专利权、专有技术使用权转让 `0.0003`。证券交易另行处理，本文不实现，也不把法律附件的基础税率当作已涵盖后续减征政策的现行实缴率。

营业账簿：

```text
C = 当前账簿记载的实收资本（股本）+ 资本公积
P = 已缴纳印花税所对应的资本计税金额（不是上一月余额）
本次应税增量 = max(C − P, 0)
应纳精确值 = 本次应税增量 × 0.00025
```

资格成立时另按 S6 处理减半。例：当前资本合计 1,200,000，已税计税金额 1,000,000；本次增量 200,000，原税额 50，减半后 25。资本曾减少后恢复到既有已税金额，不重复计税；注册资本不自动等于实收资本。

小白背面：“这里看合同/账簿记载的法定计税依据，不是把你目录里的每张发票都收一次税。”

## 8. 企业所得税：年累计预缴与年度税额分开

首轮适用居民企业、查账征收、按实际利润额预缴的普通场景。个人独资/合伙等不直接套本模型；核定征收、境外抵免、汇总纳税或特殊优惠另设适配器。

会计利润来自正确期间的账簿/利润表，包括已销成本、期间费用、税金及附加、折旧摊销等。VAT 销项/可抵扣进项通常不作为利润表收入/成本；不可抵扣 VAT 按业务性质计入相关资产、成本或费用，不能一律剔除。

```text
年度应纳税所得额 Y = 收入总额 − 不征税收入 − 免税收入 − 法定扣除 − 可弥补亏损
也可从会计利润开始逐项调增/调减，必须完整列明税会差异
年度应纳税额 = Y × 适用税率 − 依法减免 − 依法抵免
```

预缴不能把年度汇算的所有调整机械搬来。按 S5/S13 的实际利润额及当期申报表允许项目形成累计预缴基数 `P_ytd`，政策性扣除、免税、减计和弥补亏损逐项绑定表单口径；不从“销项未税 − 采购未税”直接推它。

```text
累计应纳预缴税额 C_ytd = f(P_ytd, 当期适用企业资格与优惠)
本期应补预缴 = max(C_ytd − 本年此前已预缴税额, 0)
累计多预缴对照 = max(本年此前已预缴税额 − C_ytd, 0)
```

多预缴只显示对照及待处理，不宣称自动退税。应纳基数为负时应缴为零，但亏损数额保留为事实，不能在记录层把亏损抹成零。

S6 小型微利条件：非限制禁止行业，同时年应纳税所得额不超过 300 万、从业人数不超过 300、资产总额不超过 5,000 万。员工含符合范围的派遣用工；人数与资产按季度平均值形成年度指标，新设企业和六税两费的判定周期按对应条款处理。不能用单个季度末值或当前销项规模替代所有条件。

```text
符合当期小型微利优惠：Y × 25% × 20% = Y × 5%
不符合且无其他适用优惠：一般法定税率 25%
季度平均人数/资产 = (季初 + 季末) ÷ 2
全年季度平均值 = 各季度平均值之和 ÷ 4（非完整经营年按政策处理）
```

300 万是资格门槛，不是超过后仍对前 300 万保留 5% 的累进档。年内预缴按当期适用暂判口径记录，年度条件变化要提示重算，不保证全年一直 5%。高新 15% 等优惠不能与 5% 随意叠乘。

合成例：Q1 累计预缴基数 100,000，符合小型微利，累计税额 5,000；Q2 累计基数 160,000，累计税额 8,000，此前已预缴 5,000，则 Q2 本期应补 3,000。不能把 5,000+8,000 当半年应纳；也不能只凭 Q2 发票差额替代累计利润。

小白背面：“季度交的是全年税款的预缴。先看年初到现在累计应交，再减去今年以前已经预缴的金额。”

## 9. 季度合成账例与独立预期

本表模拟钢材类贸易的月度/季度问题类型，不含关联任务的真实数量、票号、企业或金额。可把月份平移到 Q2 验证同一算法；不能标作真实 Q1 已核对。

|---|---:|---:|---:|---:|---:|---:|
| 2026-01 | 13,000 | 20,000 | 0 | 3,000 | 0 | 10,000 |
| 2026-02 | 26,000 | 13,000 | 0 | 10,000 | 3,000 | 0 |
| 2026-03 | 19,500 | 6,500 | 0 | 0 | 13,000 | 0 |

逐月应纳合计 16,000，季末留抵 0。若三个月实际附加计税基础分别等于这些应纳金额，并且城市 7%、教育 3%、地方教育 2%、六税两费减半均适用且不存在教育免征，则附加分别 0、180、780，共 960。这个“若”是显式合成条件，不能由 VAT 结果假造支付证据。

## 10. 解释模板验收

每个公式必须同时有：正常例、边界例、缺证据例、不可适用例、跨期例和政策变更例。对解释逐项检查：

1. `run_id / snapshot_id / bundle_hash / formula_version` 与正面完全一致。
2. 展示数字逐项来自 trace；含税、未税、票面税额、应纳、已缴标识正确。
3. 条件真实且可见，例如“本例已确认六税两费资格”不能改成“所有企业都减半”。
4. 税种/时间/地区的规则匹配理由正确，未知不作肯定叙述。
5. 存在缺资料、非支持场景或舍入策略未核验时，解释的是阻断原因，不输出完整确定税额。
6. 文案中不出现“系统已报税”“保证节税”“你还应补多少票”等越界结论。

两类补充样例的定义：**跨期例**指同一业务跨月、跨季或跨年时的递推（留抵、已预缴、亏损、折旧与摊销差异），预期值由逐期独立手算得到，不能用总额轧差反推；**政策变更例**指同一业务在规则包新旧版本下各算一次，必须给出两条独立预期值与差异归因，并验证旧属期不被新规则回填、两版参数不被混合使用。

内容复核记录应包含 reviewer、核验日期、官方依据、适用范围、算法与预期例；AI 可辅助起草，不能自行给未核验规则签发 `reviewed`。
