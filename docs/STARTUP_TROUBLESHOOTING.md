# 启动失败与浏览器兜底

本文的新诊断和兜底能力随 main 源码维护，功能来源为 `codex/fix-backend-startup-probe`；
**已发布的 v0.3.0-alpha.2 ZIP 尚不包含这些改动**。Windows 原生弹窗、浏览器前台
拉起和新成品仍须真机验收。合成传输测试只能证明代码中的失败机制，不能还原
每一台公测电脑的系统环境。

## 先判断失败阶段

“启动探测失败”不能直接等同于端口占用。后台服务可能已成功启动，但宿主没有
完整收到或通过校验的响应。失败后宿主会清理自己启动的后端，因此稍后检查到
“没有监听者”不能解释之前的失败。

在 Windows 按 `Win + R`，输入 `%LOCALAPPDATA%\InvoiceHub\runtime`：

| 文件 | 用途 |
|---|---|
| `startup-diagnostic-<宿主PID>.txt` | 本次失败原因、程序/配置位置、当前监听者和日志路径 |
| `startup_probe.log` | 最近一次启动的宿主与 Python PID、尝试次数、耗时、清理前存活状态、失败接口和阶段 |
| `server_stderr.log` | Python 初始化、依赖或权限异常，以及服务启动记录；其中 INFO 不一定是错误 |
| `server_stdout.log` | 后端收到的 HTTP 请求和响应状态；200/204 不等于宿主已经完整收到响应 |

`startup_probe.log` 的 `connect/headers/body/status/deadline` 表示连接、响应头、
正文、HTTP 状态或总时限阶段。`received/expected` 以响应字节计数，`os_code`
为可用的系统错误码；`child_before_cleanup` 表示宿主清理前的 Python 状态。
`handshake_ready` 只表示初次握手完成，后续仍有偏好和 ownership 复验。
文件每次初次握手覆盖，排障时须核对 PID；不得把旧日志当作新一次启动的证据。

Windows 加固版在创建 Python 前先写入本次 `host_pid + spawn_pending`；创建失败
记录 `stage=spawn` 与系统错误码，避免把上次成功握手误认为本次结果。宿主清除
继承的 `PYTHONHOME`，保证内置解释器使用自己的标准库；不修改系统环境变量。
若出现 `encodings` 初始化失败，先确认使用包含这项加固的新包和完整解压目录。

| 观察 | 处理方向 |
|---|---|
| 有明确占用 PID，或绑定被拒绝 | 正常退出对应程序；无监听者但系统拒绝绑定时再检查系统端口保留/应用权限 |
| Python 提前退出，stderr 有异常 | 按异常定位 runtime、缺失依赖、解压完整性或可写目录 |
| Python 已监听、响应成功，探测仍失败 | 查看宿主响应读取/身份检查的阶段、计数和系统错误码 |
| 后端验证通过，仅桌面窗口创建失败 | 使用下面的浏览器兜底 |

## 浏览器模式

两种界面共用同一个后端和数据目录。浏览器模式不能绕过端口、manifest、PID、
身份签名或接口契约检查。

后端验证成功、Windows 桌面窗口创建失败时，会询问“是否改用系统浏览器继续使用”：

- 选择“是”：重新验证后端身份后打开浏览器，宿主与托盘继续管理后端。
- 选择“否”：清理本次后端并退出，保留诊断。
- 选择期间后端退出或身份改变：停止打开浏览器，显示失败。

兜底只改变这一次启动，不覆盖设置中的启动偏好。它覆盖窗口创建错误；窗口
创建成功后白屏、运行中崩溃或 Tauri 自身尚未进入 setup 的故障不在该机制内。

也可以完整退出 InvoiceHub，在解压目录打开终端，执行：

```powershell
.\InvoiceHub.exe --browser
```

使用 `--desktop` 可只在本次尝试桌面模式。两个参数不能一起使用。
已有实例运行时，第二次启动仍只唤回原来的界面；先从页面或托盘完整退出才能切换。
长期偏好仍在设置页保存。关闭浏览器或隐藏桌面窗口不会停止独立监控。

## 给维护者的验证范围

响应读取按 Content-Length、无正文状态和 chunked 分帧；明确收齐后不等待 TCP
关闭。缺失字节、歧义长度、重复身份头、超限响应及未经定义的 trailer 均继续拒绝。
只有没有明确 framing 的旧式响应才依赖正常 EOF；不能把所有连接重置都当成功。

每轮握手和连接/写入/读取共享 5 秒预算，启动重试共享 20 秒预算；后端提前退出
不继续空等。诊断只输出固定接口、阶段、计数和系统错误，不输出令牌、签名
challenge、完整响应头或业务正文。收集外部日志时仍不要把真实附件或路径提交到公开仓库。

相邻验证包括传输分片、完整后 reset、204、chunked、保持连接、截断、大小上限、
重复头、总超时、child 提前退出，以及浏览器兜底的确认、拒绝、身份失效和打开失败。
源码自动化通过后仍需分别验收 Windows 默认配置、正式入口、单实例、托盘、
monitor 保留/停止、原生面板、浏览器拉起和包含改动的新 ZIP。
